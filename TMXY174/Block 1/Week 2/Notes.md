 **Project lifecycle** is a structured sequences of phrases that it is used to organise and manage a project from it's beginning through completion

 The general steps int terms of cycle completion
 ->
* 1 - Initiation
* 2 - Planning
* 3 - Execution
* 4 - Monitoring and Execution
* 5 - Closure



## Phase 1: initiation

Defining or what the project is going to be from a high level

**Project Charter** A document developing during project initiation that formally establish the project and supports a approval to proceed.

**feasibility study** is an assessment undertaken during project initiation to determine whether a project proposal is practical & achievable - technical, financial, time constraints

## Phase 2 Planning

Establishing a timeline for the completion / duration of the project

**Project objective** focusing on the scope of the project, the timeline of delivery, the cost of the project, the resources that will be used and the risks associated with the project (risk management)

**Worked Based Structure** is breaking down large concepts into smaller pieces of works, more manageable tasks or components to support project planning and delivery

**Key Activities**
- Identity risks and mitigation strategies
- Develop a plan for budget & resources
- creating a project schedule with mile stones and deadlines


**Outcomes**
- Project management plan
- Work breakdown Structure

Phase 5: testing
Before release, the system must be thoroughly tested to ensure that it meets stakeholder requirements and functions correctly. Testing may include:

unit testing
integration testing
system testing
user acceptance testing (UAT).
This phase should not be rushed. The system is only ready to move forward when all tests are passed and the team is confident in its quality.

Phase 6: deployment
Once tested and approved, the system is released into the live environment. Deployment typically involves configuration, data migration and final verification checks to ensure that everything works as intended.

Phase 7: maintenance
After the system goes live, it enters long-term support. Updates, bug fixes, performance improvements and new features may all be required. These activities are usually managed through a service-level agreement (SLA) or support arrangement, allowing the project to close while ensuring ongoing stability and improvement
